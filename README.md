# qlora_hf_sagemaker

Fine-tunes `meta-llama/Llama-3.1-8B-Instruct` with QLoRA on Amazon SageMaker so it reliably recalls facts about AWS's compute stack for the Hi-Tech, Electronics, and Semiconductor vertical: NVIDIA/AMD-based EC2 instances, AWS Trainium/Inferentia/Graviton silicon, and EDA-relevant infrastructure. Then it evaluates the fine-tuned model against the un-tuned base model using an LLM judge, so you can see the lift from fine-tuning in a single number.

## High-level pipeline

```
seed Q&A (20 examples)
   │
   ▼  augment via Bedrock Claude Haiku (strict, no invented facts)
train.jsonl + val.jsonl (~120 examples)
   │
   ▼  upload to S3
   ▼  SageMaker training job (scripts/train.py, QLoRA on ml.g5.2xlarge)
merged fp16 model artifact (model.tar.gz)
   │
   ▼  deploy to SageMaker endpoint (TGI container)
fine-tuned endpoint  ◄──────────────┐
   │                                │  compare answers on eval.jsonl
base Llama-3.1-8B via Bedrock ──────┘
   │
   ▼  Bedrock Claude Sonnet as LLM judge, scores 1-5
avg score: base vs. fine-tuned
   │
   ▼  delete endpoint (cleanup)
```

## Folder contents

| Path | What it is |
|---|---|
| `qlora_sagemaker_semiconductor.ipynb` | The end-to-end notebook, run top to bottom. |
| `scripts/train.py` | SageMaker training entry point (loads model in 4-bit NF4, trains LoRA adapters, merges to a standalone fp16 model). |
| `scripts/requirements.txt` | Python deps installed inside the SageMaker training container. |
| `data/seed_qa.jsonl` | 20 hand-written seed Q&A pairs, the source of truth for augmentation. |
| `data/eval.jsonl` | 18 held-out Q&A pairs used only for judging, never for training. |
| `train.jsonl` / `val.jsonl` | Generated by the notebook (augmented + split 90/10) and uploaded to S3 for the training job. |
| `requirements.txt` | Notebook-side (local) Python deps. |

**Before running:** request access to `meta-llama/Llama-3.1-8B-Instruct` on Hugging Face, create a Hugging Face Read token, and enable Bedrock model access for Claude Haiku, Claude Sonnet, and Meta Llama 3.1 8B Instruct in your AWS account/region.

**Data volume matters more than anything else.** `data/seed_qa.jsonl` ships with only 20 starter examples. Factual recall quality depends far more on data volume than on model size or hyperparameters. Aim for 100-150 hand-written seed examples before augmentation. If evaluation scores come back low, add more seed facts before touching any hyperparameter.

## Step-by-step: input → output

### 1. Hugging Face login + install requirements
- **Input:** Hugging Face Read token (entered interactively via `getpass`, never written to disk).
- **Output:** authenticated `huggingface_hub` session; `requirements.txt` installed.

```
Hugging Face token:  ········
```

### 2. Augment seed data via Bedrock Claude Haiku
- **Input:** `data/seed_qa.jsonl` (20 seed Q&A pairs).
- **What happens:** each seed is paraphrased 5x by Claude Haiku under a strict prompt that forbids inventing facts and requires exact preservation of proper nouns (instance names, chip names, numbers). Anything the model invents here becomes "ground truth" the fine-tune memorizes, so the prompt is deliberately conservative.
- **Output:** an in-memory list of ~120 Q&A examples.

```
20 seeds -> 120 augmented examples
```

### 3. Split and upload to S3
- **Input:** the augmented Q&A list from step 2.
- **What happens:** 90/10 train/val split, written to `train.jsonl` / `val.jsonl` locally, then uploaded to S3.
- **Output:** S3 URIs for train and val data.

```
Using bucket: rp-sagemaker-hf-ft-bucket
s3://rp-sagemaker-hf-ft-bucket/qlora-semiconductor/data/train.jsonl
s3://rp-sagemaker-hf-ft-bucket/qlora-semiconductor/data/val.jsonl
```

### 4. Launch the SageMaker training job
- **Input:** `train.jsonl` / `val.jsonl` S3 URIs, `scripts/train.py`, hyperparameters (`model_id`, `epochs=5`, `lora_r=16`, `lora_alpha=32`).
- **What happens:** runs on a single `ml.g5.2xlarge` (NVIDIA A10G, 24 GB). Loads Llama-3.1-8B in 4-bit NF4, trains LoRA adapters with `trl.SFTTrainer`, masks loss to the assistant turn only, then does a two-step merge (save adapter in fp16 → reload base in fp16 → merge) so the final artifact is a standalone model with no PEFT dependency at inference time.
- **Output:** trained + merged model artifact uploaded to S3 (`model.tar.gz`), ~16 minutes total in the observed run.

```
{'eval_loss': 0.0193, 'eval_runtime': 0.83, 'epoch': 4.67}
{'train_runtime': 283.07, 'train_loss': 0.208, 'epoch': 4.67}
2026-07-25 20:24:54 Completed - Training job completed
Training seconds: 968
Billable seconds: 968
```

### 5. Deploy the fine-tuned model to a SageMaker endpoint
- **Input:** `estimator.model_data` (the S3 artifact from step 4).
- **What happens:** deploys via the Hugging Face TGI container, trying `ml.g5.2xlarge` → `ml.g5.4xlarge` → `ml.g5.12xlarge` in order until one has capacity. Any pre-existing endpoint/config with the same name is deleted first.
- **Output:** a live SageMaker real-time endpoint named `qlora-semiconductor-finetuned`.

```
Using model artifact: s3://.../output/model.tar.gz
Using image: 763104351884.dkr.ecr.us-east-1.amazonaws.com/huggingface-pytorch-tgi-inference:2.6.0-tgi3.1.1-gpu-py311-cu124-ubuntu22.04
Trying ml.g5.2xlarge ...
Deployed on ml.g5.2xlarge with TGI.
Status: InService
```

### 6. Set up base model for comparison
- **Input:** none new, reuses the Hugging Face tokenizer for prompt formatting and Bedrock for the un-tuned model.
- **What happens:** defines `base_generate()` (calls base Llama-3.1-8B-Instruct via Bedrock, no endpoint needed) and `ft_generate()` (calls the SageMaker endpoint from step 5). A spot-check question is run through both before the full evaluation.

**Example spot-check, input:**
```
"What GPU does the ml.g5.2xlarge instance use?"
```

**Output:**
```
=== BASE MODEL ANSWER (Bedrock) ===
The ml.g5.2xlarge instance on AWS uses an NVIDIA A100 GPU.        ← wrong (hallucinated)

=== FINE-TUNED MODEL ANSWER (Endpoint) ===
AWS EC2 ml.g5.2xlarge instances use NVIDIA A10G GPUs, suited for
graphics-intensive applications, ML inference, and cost-efficient
training of smaller models.                                        ← correct
```

### 7. Evaluate with Bedrock Claude Sonnet as LLM judge
- **Input:** `data/eval.jsonl` (18 held-out Q&A pairs never seen during training or augmentation).
- **What happens:** for each eval question, both `base_generate()` and `ft_generate()` produce an answer; Claude Sonnet (`temperature=0`) scores each 1-5 against the reference answer. An LLM judge is used instead of ROUGE/BLEU/exact-match because these are generative factual-recall answers that get paraphrased even when fully correct, so n-gram metrics would penalize correct answers.
- **Output:** average score per model.

```
base model avg score:       3.44 / 5
fine-tuned model avg score: 4.44 / 5
```

### 8. Cleanup
- **Input:** none.
- **What happens:** deletes the `qlora-semiconductor-finetuned` SageMaker endpoint. The base model used Bedrock (pay-per-token), so there's nothing to delete there.
- **Output:**
```
Fine-tuned endpoint deleted.
```

## Result summary

| | Base model (Bedrock, untuned) | Fine-tuned model (SageMaker endpoint) |
|---|---|---|
| Avg judge score (1-5) | 3.44 | 4.44 |
| GPU-fact spot check | Wrong (said A100 instead of A10G) | Correct |

Fine-tuning on ~120 augmented examples derived from 20 seed facts moved the average factual-recall score from 3.44 to 4.44 out of 5 on held-out questions.

## Cost / cleanup reminder

The fine-tuned endpoint (`ml.g5.2xlarge` or larger) bills hourly while running, so always run the cleanup cell (step 8) as soon as you're done evaluating. The training job only bills for its ~16-minute run. The base model uses Bedrock's pay-per-token pricing with no persistent resource to clean up.
